# Аппаратура rln-trace: архитектура

Документ описывает зонд направления B (своя плата) и то, что из него переиспользуется в направлении A
(альтернативная прошивка Sipeed SLogic16U3). Схема rev 0.1 лежит в [`probe-b/`](probe-b/).

## 1. Требования

| ID | Требование | Значение / решение |
|---|---|---|
| R1 | Трасса | Полный ETM (Cortex-M) через TPIU; RISC-V через PIB; 1/2/4 бита, такт от цели, выборка по обоим фронтам |
| R2 | Скорость порта | STM32F407: TRACECLK 84 МГц DDR × 4 бита = 84 МБ/с пик; потолок MIPI20 — около 100 МБ/с |
| R3 | Режим захвата | Непрерывный поток на ПК; минимум — полный интервал между двумя PPS (≤ 84 МБ) |
| R4 | Метки событий | PPS, SMA1, SMA2, маркеры; шаг единицы нс; привязка к номеру кадра трассы |
| R5 | Отладка | SWD и 4-проводной JTAG; CMSIS-DAP v2 с JTAG-последовательностями (`DAP_JTAG_Sequence`): OpenOCD, pyOCD, probe-rs, openFPGALoader работают с любой JTAG-целью — ARM, RISC-V, FPGA (SVF). Универсальный сдвиговый движок в ПЛИС; Spy-Bi-Wire (MSP430, через mspdebug) — следующий этап |
| R6 | Разъём цели | MIPI20 по RISC-V Trace Connectors 1.0 (совпадает с Cortex Debug+ETM); Mictor не поддерживается |
| R7 | Уровни | VREF 1,2–3,6 В, трансляторы, защита от ESD и перенапряжения, Hi-Z по умолчанию |
| R8 | Внешние разъёмы | USB-C (USB 3.2 Gen1), SMA1 и SMA2 — двунаправленные триггеры; SMA1 может быть опорой 10 МГц (TTL) |
| R9 | Питание цели | 5 В на контакты 11/13 MIPI20 через ключ с ограничением тока, с измерением тока |
| R10 | Монтаж | Только QFP/QFN, ПЛИС в QN88 |
| R11 | Совместимость | Интерфейс трассы повторяет ORBTrace, Orbuculum работает без патчей |
| R12 | Тулчейн | Открытый (Yosys + nextpnr/Apicula) и проприетарный Gowin EDA |

Вне рамок rev 0.1: функции логического анализатора (их закрывает SLogic16U3), Mictor-38, cJTAG, RVSWD,
выдача TRIGIN в цель.

## 2. Структурная схема

![Структурная схема зонда B](img/system.svg)

| | A: прошивка SLogic16U3 | B: свой зонд |
|---|---|---|
| ПЛИС | Gowin GW5AT-LV15 (CSP), USB3 на встроенных SerDes | Gowin GW2AR-18 QN88, 64 Мбит SDRAM в корпусе |
| USB3 | IP-ядро Gowin в ПЛИС | CH569W (QFN68), HSPI к ПЛИС |
| Функции | трасса + события на свободных каналах | трасса + события + SWD/JTAG + TgtPwr + UART |
| Вход | компараторы с порогом 0–6 В, только приём | трансляторы от VREF, вход и выход |
| Тулчейн | только Gowin EDA | Gowin EDA и открытый |
| Главный риск | схема закрыта, неизвестна разводка тактовых входов | объём работы, целостность сигнала на 100 МГц DDR |

Всё, что зависит только от протокола трассы (приём TPIU, метки времени, пакетизация, формат потоков,
утилита на ПК), пишется один раз и переносится между Tang Nano 20K, SLogic16U3 и своей платой.

## 3. Внешние интерфейсы

### MIPI20 (контакты по RISC-V Trace Connectors 1.0)

| Контакт | Сигнал | Направление (от зонда) | Примечание |
|---|---|---|---|
| 1 | VREF | вход | Питает сторону цели у трансляторов, измеряется АЦП |
| 2 | TMS / SWDIO | двунаправленный | Направление переключает ПЛИС |
| 4 | TCK / SWCLK | выход | |
| 6 | TDO / SWO | вход | SWO — UART или Manchester |
| 8 | TDI | выход | |
| 9 | GNDDetect | — | На зонде всегда земля |
| 10 | nRESET | открытый сток + контроль | Зонд видит сбросы цели |
| 11, 13 | GND / TgtPwr | выход 5 В | Перемычка JP1, по умолчанию GND |
| 12 | TRC_CLK | вход | На тактовый вход ПЛИС |
| 14, 16, 18, 20 | TRC_DATA[0..3] | вход | |
| 3, 5, 15, 17, 19 | GND | — | |
| 7 | ключ | — | Вывод удалён: на кабелях Cortex Debug+ETM отверстие 7 часто заглушено |

Вилка — 2×10 с шагом 1,27 мм в кожухе с ключом (например, Samtec FTSH-110-01-L-DV-K), вывод 7 удалён.
Шлейф — плоский 0,635 мм, 7–10 см (не длиннее 15 см), розетки IDC с ключом, выводы один в один
(например, Samtec FFSD-10-D-03.00-01-N). Нечётные жилы — земля, поэтому каждая линия трассы в шлейфе идёт
между двумя земляными. Подробнее — в [`doc/bench.md`](../doc/bench.md#шлейф-mipi20).

### USB-C

USB 3.2 Gen1 через CH569. Ориентацию разъёма определяет компаратор по линии CC1, пары SuperSpeed
переключает мультиплексор CBTL02043A. USB2 HS остаётся для DFU и как запасной путь.

### SMA1, SMA2

Двунаправленные 3,3 В LVCMOS, по умолчанию вход. Транслятор с выводом направления (SN74LVC1T45),
33 Ом последовательно (согласование с коаксиалом 50 Ом), TVS, отключаемая нагрузка 50 Ом.
SMA1 заведён на вход PLL ПЛИС и может быть опорой 10 МГц (TTL-выход GNSS-генератора). Синус не принимается.

## 4. Входной каскад

Каждая линия MIPI20: TVS-массив у разъёма → 33 Ом → транслятор.

![Входной каскад](img/frontend.svg)

- **Трасса, TDO, контроль nRESET** — SN74AVC8T245 на приём (DIR = 0, B → A).
- **SWDIO, SWCLK, TDI** — SN74AVC4T245: группа 1 двунаправленная (SWDIO), группа 2 на выход.
- **nRESET** — открытый сток на 2N7002, состояние читается обратно через транслятор.
- Сторона цели трансляторов питается от VREF через фильтр 10 Ом + 1 мкФ. Семейство AVC работает от 1,2 В,
  имеет Ioff и изоляцию по VCC: при VREF = 0 выходы в Hi-Z.
- После включения оба транслятора выключены (OE подтянут вверх). Прошивка включает их,
  только когда VREF в окне 1,2–3,6 В (ADS1115, канал 0).
- Питание цели: AP2161 (ограничение тока, флаг перегрузки), шунт 0,1 Ом + INA219,
  на контактах 11/13 10 пФ по спецификации.

## 5. ПЛИС: раскладка и гейтвар

GW2AR-LV18QN88C8/I7: 20 736 LUT4, 828 Кбит BSRAM, 64 Мбит SDR SDRAM в корпусе, 66 пользовательских выводов.
Распиновка — по Gowin UG115E v1.7.2 (колонка QN88 со SDRAM). Все VCCIO — 3,3 В
(выводы 3/12/64 — общая шина VCCX/VCCIO2/6/7).

| Банк | Назначение |
|---|---|
| 6 | Трасса: TRC_CLK на GCLKT_6 (вывод 10), данные на 17–20; TDO, контроль nRESET, OE трассы; SMA1 на LPLL2_T_in (13) |
| 7 | Генератор 50 МГц на LPLL1_T_in (4) |
| 0 | SWDIO, направление SWDIO, SWCLK, TDI, nRESET, OE отладки, светодиоды |
| 1 | Управление HSPI, HTCLK от CH569 на GCLKT_1 (77) |
| 4, 5 | Данные HSPI D0–D15 |
| 3 | MSPI-флеш, RECONFIG_N, MODE0/1, SMA2 на GCLKT_3 (63), направление SMA |
| 2 | JTAG ПЛИС |

Занято 49 выводов из 66, полная таблица — [`probe-b/kicad/pinmap.csv`](probe-b/kicad/pinmap.csv).

### Конвейер приёма трассы

![Структура гейтвара](img/gateware.svg)

1. **IDDR + IODELAY** (домен TRC_CLK): за такт два ниббла, задержка каждой линии настраивается.
2. **Сборка слов** 32 бита → асинхронный FIFO в системный домен.
3. **Поиск синхронизации:** окно 32 бита сравнивается с `0x7FFFFFFF` на всех 32 сдвигах по биту (подходит для портов 1/2/4 бита).
4. **Выравнивание кадров:** счёт байт по модулю 16 от последнего синхрослова; синхрослова вырезаются.
5. **Фильтр idle:** пустые кадры отбрасываются.
6. **Нумерация:** каждый кадр получает 64-битный номер — по нему связываются трасса и события.

Автомат синхронизации деформатора:

![Автомат деформатора TPIU](img/fsm.svg)

Для RISC-V PIB есть «сырой» режим без деформатора.

### Метки времени

![Связь трассы и событий](img/events.svg)

- Счётчик 64 бита на PLL 200–250 МГц от опоры (10 МГц с SMA1 или местный генератор).
- Запись события, 16 байт: тип (PPS, фронты SMA, служебная метка, ресинхронизация, переполнение),
  флаги, номер кадра трассы (48 бит), время (64 бита).
- Служебные метки «кадр N пришёл в момент T» идут периодически — по ним время пересчитывается
  внутри интервала. Для точной корреляции цель пишет ITM-маркер по PPS: задержка FIFO ETM внутри
  цели плавает.

### Буфер и мост к USB-чипу

- Кольцо в SDRAM (8 МБ, ~100 мс на пике 84 МБ/с). Обратного давления на цель нет: при переполнении
  кадры теряются, в журнал пишется событие «переполнение».
- Пакетизатор с приоритетами: ответы на команды → события → трасса.
- Мост к USB-чипу — сменный модуль за общим интерфейсом FIFO (потоки трассы, событий и ответов
  отдельно, обратный поток команд). Под ним один из двух вариантов:
  - **HSPI → CH569** (текущая схема rev 0.1): 16 бит до 120 МГц (~237 МБ/с); на макете 8 бит (~95–119 МБ/с).
    Протокол на проводе — [`doc/ch569-hspi.md`](../doc/ch569-hspi.md).
  - **UHSIF → CH32H417** (рассматривается, см. ниже): синхронный FIFO с флагами, 16 бит ~250 МБ/с,
    32 бита до 500 МБ/с.

### Альтернатива CH569: CH32H417

WCH CH32H417 (QFN128, вышел в конце 2025 г.) — кандидат на роль USB3-моста в зонде B.
Решение принимается по результатам шага 0 на плате с этим чипом.

| | CH569W | CH32H417QEU6 |
|---|---|---|
| Ядра | RISC-V3A, 120 МГц | RISC-V5F 400 МГц + RISC-V3F 160 МГц |
| ОЗУ | десятки КБ (RAMX до 96 КБ) | 896 КБ |
| USB3 | device/host, ~5 Гбит/с | device/host; замер WCH на CH32H416MEU6 (QFN88): ~450 МБ/с на приём и ~447 МБ/с на передачу, одновременная работа UHSIF скорость не снижает |
| Шина к ПЛИС | HSPI 8/16/32 бит, без флагов заполнения | UHSIF 8/16/24/32 бит до 125 МГц, режим «ведомый для ПЛИС», флаги WRNF/AF#/RDNE/AE#, 4 канала по 8 буферов |
| Type-C | внешний компаратор на CC1 | встроенный контроллер Type-C/PD (CC1/CC2); мультиплексор SS-пар всё равно внешний — линия USB3 одна |
| Открытость | HydraUSB3, свои исходники | стек USB3 device в исходниках; UHSIF у WCH — закрытая `libUHSIF.a`, у нас — открытый драйвер [`fw/uhsif`](../fw/uhsif/) (на железе ещё не проверен) |
| Корпус | QFN68 | QFN128; по даташиту V1.8 UHSIF полностью есть и в QFN88 (CH32H416MEU6), в QFN68 (CH32H415WEU6) — неполный |

![CH32H417 как USB3-мост](img/ch32h417/12-block.svg)

**UHSIF глазами ПЛИС** (по UHSIF Development Reference Manual V1.0). ПЛИС — ведущий: выдаёт PCLK,
SEL[1:0] (номер канала), CS#, WR#, RD#, OE#, EOP# (конец пакета или пакет нулевой длины) и DATA.
Чип отвечает флагами: WRNF — «приёмный буфер не полон», AF# — «почти полон» (порог задаётся),
RDNE — «есть что читать», AE# — «почти пуст». WRNF снимается через 2 такта после WR#, данные при чтении
появляются через 2 такта после RD#. Это та же схема, что у Cypress FX3 Slave FIFO. Временные
диаграммы и окно захвата при 125 МГц — в [`doc/ch32h417-uhsif.md`](../doc/ch32h417-uhsif.md#шина-со-стороны-плис).

Выводы, питание и такт UHSIF:

![Выводы UHSIF](img/ch32h417/10-pins.svg)

![Домены питания](img/ch32h417/11-power.svg)

Выводы UHSIF питаются от VIO18; без резистора на XO после включения он 1,8 В. Если банк ПЛИС к UHSIF
на 3,3 В, VIO18 надо замкнуть на VDDIO = 3,3 В: иначе ПЛИС выдаёт 3,3 В в выводы, питающиеся от 1,8 В,
пока прошивка не подняла напряжение. Если банк на 1,8 В, XO оставить без резистора. 125 МГц
в таблице WCH указаны при 1,8 В.

![Такт UHSIF](img/ch32h417/09-clock.svg)

Что даёт зонду:
- четыре канала UHSIF ложатся на потоки «трасса / события / ответы DAP / команды» без общего мультиплексора;
- флаги заполнения дают честное управление потоком вместо подсчёта пакетов;
- запас полосы: 16 бит ≈ 250 МБ/с при 84 МБ/с пике трассы, 32 бита — если хватит выводов;
- второе ядро — CMSIS-DAP и режим USB-Blaster отдельно от USB3.

Риски:
- конфигурация UHSIF у WCH — только через закрытую библиотеку; её поведение восстановлено, есть открытый
  драйвер [`fw/uhsif`](../fw/uhsif/) (в эмуляторе совпадает с библиотекой, на железе ещё не проверен,
  см. [`doc/ch32h417-uhsif.md`](../doc/ch32h417-uhsif.md));
- справочное руководство (TRM) только на китайском, экосистема молодая;
- плата зонда B и адаптер ПЛИС стенда меняются под другую шину и раскладку.

### Языки

- **SystemVerilog** — и ядра (деформатор, метки времени, пакетизатор, SWD/JTAG, CSR, мост HSPI), и
  платформенный слой (примитивы Gowin: IDDR, IODELAY, PLL, SDRAM; верхние модули плат). Подмножество,
  которое читают Verilator, Yosys и Gowin EDA.
- Тесты — Verilator с тестбенчами на C++: модели внешних микросхем, сквозные прогоны на записях
  реального потока, проверка потока самотеста тем же кодом, что и на ПК (`sw/usbstream/check.c`).

## 6. Отладка

CH569 разбирает CMSIS-DAP v2 (протокольное ядро [free-dap](https://github.com/ataradov/free-dap)),
а на линии сигналы выдаёт движок в ПЛИС. Совместимость проверяется с OpenOCD, pyOCD, probe-rs и openFPGALoader.

- **Универсальный сдвиговый движок** (по образцу MPSSE): N тактов с заданными TMS/TDI, захват TDO,
  TCK до 30–50 МГц с подстройкой момента выборки TDO. На нём выполняются `DAP_JTAG_Sequence`
  и `DAP_SWJ_Sequence`, поэтому через OpenOCD работает любая JTAG-цель: ARM, RISC-V (включая ESP32),
  FPGA Altera/Intel, Xilinx, Lattice, Gowin (SVF, `pld`, openFPGALoader), boundary scan.
- **Ускорение транзакций SWD/JTAG-DP** строится поверх движка: чтение и запись DP/AP целиком в ПЛИС,
  без обмена по USB на каждый бит.
- **Режим USB-Blaster для Quartus** (следующий этап). Quartus Programmer работает только с USB-Blaster,
  поэтому зонд по команде переключается в отдельный режим: заново перечисляется на USB как
  USB-Blaster (FT245, VID:PID 09fb:6001, full-speed, 64-байтные пакеты) и выполняет его протокол —
  побитовый режим и shift-режим — на том же сдвиговом движке. Образец — [`au/pico-usb-blaster`](../au/pico-usb-blaster)
  (MIT, tinyUSB). Только JTAG: режимы AS/PS требуют линий nCONFIG, nCE, nCS, CONF_DONE, nSTATUS,
  которых на MIPI20 нет. В прошивке для публичных сборок VID:PID Altera — отдельный вопрос, режим
  можно оставить опцией сборки. До его готовности: Quartus выгружает SVF/JAM, прошивка — через
  OpenOCD или openFPGALoader.
- **Следующий этап — Spy-Bi-Wire для MSP430:** отдельный режим движка и драйвер для mspdebug (OpenOCD
  MSP430 не поддерживает). Новых линий не нужно: пассивный переходник подаёт SWCLK на вывод TEST
  (SBWTCK), а SWDIO — на RST (SBWTDIO). Все MSP430 с выводом TEST умеют SBW; старые без TEST имеют
  4-проводный JTAG на отдельных выводах и подключаются как обычная JTAG-цель.
- **Ограничения:** цели 5 В не поддерживаются (VREF 1,2–3,6 В). На MIPI20 нет nTRST и RTCK: JTAG
  сбрасывается через TMS (так делает OpenOCD), ARM7/9 с адаптивным тактом работают на фиксированной
  низкой частоте TCK. Для редкой цели, которой нужен nTRST или RTCK, можно временно вывести линию
  с разъёма EXP (запасные выводы ПЛИС, только 3,3 В, без транслятора).

## 7. USB-интерфейсы

| Интерфейс | Класс / подкласс | Содержимое |
|---|---|---|
| Трасса | 0xFF / 0x54 ('T'), протокол 0x01 (TPIU) | 16-байтные кадры TPIU, как у ORBTrace |
| События | 0xFF / свой подкласс | Записи по 16 байт |
| CMSIS-DAP v2 | 0xFF, строка «CMSIS-DAP» | Команды отладки |
| UART цели | CDC-ACM | Виртуальный UART |
| Управление | vendor requests | CSR ПЛИС, TgtPwr, VREF, ток, калибровка задержек |
| Обновление | DFU | Прошивка CH569 и битстрим ПЛИС одним образом |

Следующий шаг совместимости — протокол orbflow (Orbuculum 2.2+): события можно отдавать отдельным тегом.

## 8. Питание

USB 5 В → предохранитель → TLV62569 на 3,3 В (2 А) и TLV62569 на 1,0 В (ядро ПЛИС, включается по PG от 3,3 В).
VCCPLL ПЛИС — через ферритовую бусину. CH569 сам делает 1,2 В встроенным LDO.

## 10. Открытые вопросы rev 0.1

1. Посадка QN88 нарисована по номинальным размерам — сверить с чертежом UG229.
2. Центральная площадка CH569W QFN68 — по даташиту CH569DS1.
3. PB15 = HD14 одновременно RST# CH569: отключить RST# в конфигурации до работы HSPI 16 бит. На плате
   стенда (WCH CH569 EVT) RESET_EN уже 0, PB15 — GPIO.
4. MODE[1:0] = 00 → MSPI (UG290, табл. 5-2) — проверить.
5. Полярность SEL у CBTL02043A и выбор разъёма USB-C на 24 контакта.
6. Номиналы 33 Ом на линиях трассы — подобрать на макете.
7. USB3-мост: CH569W (HSPI) или CH32H417QEU6 (UHSIF). Критерии: скорость ПЛИС → файл на ПК на шаге 0,
   возможность обойтись без `libUHSIF.a` или законно её распространять, доступность чипа.
