# hspi2usb — мост HSPI → USB3

ПЛИС шлёт пакеты по HSPI ([`gw/cores/selftest_hspi.sv`](../../../gw/cores/selftest_hspi.sv) на шаге 0,
позже — пакетизатор трассы), CH569 ставит их в очередь и отдаёт в EP2 IN. На ПК — тот же
[`sw/usbstream`](../../../sw/usbstream): блоки самотеста от ПЛИС имеют формат
[`stream.h`](../usbstream/stream.h), пакет HSPI — один блок.

## Как устроено ([`bridge.c`](bridge.c))

- Пул из 16 блоков по 4096 байт в RAMX.
- HSPI в режиме приёмника, два слота DMA попеременно (RX_TOG_EN). После хорошего пакета блок уходит в
  очередь, слот получает свежий блок из пула; адрес меняется, пока HSPI принимает во второй слот
  (окно t3–t4 по даташиту). Пакет с ошибкой CRC или номера остаётся в слоте и перезаписывается.
- EP2 IN отправляет голову очереди: на USB3 — пачкой до 4 пакетов по 1024, на USB2 — по 512 байт.
  Пустая очередь — точка не готова, хост ждёт.
- Пул пуст — пакет HSPI принимается в отдельный блок и считается потерянным (`dropped`).
  Управлять HTACK CH569 программно нельзя, поэтому обратного давления на ПЛИС здесь нет; USB3 в
  несколько раз быстрее HSPI на стенде, так что это аварийный случай.
- Пул и очередь общие для прерываний HSPI, USB и главного цикла: доступ при запрещённых прерываниях.

Какой слот только что заполнен, берётся из флага RB_HSPI_RX_TOG (он указывает на слот, занятый сейчас).
Это прочтение даташита, проверить на стенде.

## Команды EP1

`usbstream -C КОМАНДА`: `SRCH` — данные из HSPI (по умолчанию), `SRCI` — внутренний источник:
главный цикл сам заполняет блоки в формате `stream.h` и ставит их в ту же очередь — так мост
проверяется без ПЛИС; `STAT` — счётчики. Остальные команды — как в примере HydraUSB3 (`USBS`, `LOGR`).

```sh
make                       # WCH EVT, HSPI 8 бит; HSPI_WIDTH=16 для зонда B
make flash                 # плата в загрузчике
../../../sw/usbstream/usbstream -C SRCI -t 10 -C STAT
```
