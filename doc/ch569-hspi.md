# HSPI CH569: протокол на проводе

Источник — даташит CH569/565 V1.0, глава 10 «HSPI» (китайская редакция, CH569_565DS). Регистры и
порядок настройки совпадают с драйвером BSP
[`au/hydrausb3_fw/wch-ch56x-bsp/drv/CH56x_hspi.c`](../au/hydrausb3_fw/wch-ch56x-bsp/drv/CH56x_hspi.c).
Модель приёмника для тестов — [`gw/test/models/ch569_hspi.h`](../gw/test/models/ch569_hspi.h),
передатчик ПЛИС — [`gw/cores/hspi_tx.sv`](../gw/cores/hspi_tx.sv).

## Линии

Одна шина данных HD[31:0] на оба направления (полудуплекс), у каждой стороны четыре линии передатчика и
четыре линии приёмника. Передатчик одной стороны соединяется с приёмником другой.

| Передатчик | Направление | Приёмник | Что значит |
|---|---|---|---|
| HTCLK | → | HRCLK | такт передатчика, по нему приёмник защёлкивает данные |
| HTREQ | → | HRACT | запрос передачи, высокий на всё время пакета |
| HTRDY | ← | HTACK | приёмник готов: есть свободный буфер DMA |
| HTVLD | → | HRVLD | данные на шине действительны |

В схеме зонда rev 0.1 цепь к PA18 CH569 подписана `HSPI_HRACK`; по даташиту этот вывод — HRACT, вход
запроса передачи. Направления в схеме верные.

Для ПЛИС → CH569 (поток трассы): ПЛИС выдаёт HRCLK, HRACT, HRVLD и HD, читает HTACK. Для CH569 → ПЛИС
(команды): CH569 выдаёт HTCLK, HTREQ, HTVLD и HD, ПЛИС отвечает HTRDY.

## Пакет

Всё передаётся младшими битами вперёд: 8-, 16- или 32-битными тактами.

| Часть | Размер | Содержимое |
|---|---|---|
| Заголовок | 4 байта | [31:30] TLL2B — сколько байт последнего такта занято, если длина не кратна ширине шины; [29:26] TSQN — номер пакета 0–15; [25:0] USDF — поле пользователя (у CH569: UDF0 для чётных номеров, UDF1 для нечётных) |
| Данные | 1–4096 байт | В RAMX через DMA, два буфера попеременно (RX_TOG_EN) |
| CRC | 2 или 4 байта | По заголовку и данным. CRC16, полином 0x8005, при шине 8 и 16 бит; CRC32, полином 0x04C11DB7, при 32 битах |

Номер пакета растёт только после успешной передачи; приёмник сверяет его со своим (RB_HSPI_NUM_MIS)
и CRC (RB_HSPI_CRC_ERR). Длина пакета на стороне приёмника — по снятию HRACT.

## Обмен

1. Передатчик поднимает HTREQ.
2. Приёмник, если может принять, поднимает HTACK (у передатчика — HTRDY).
3. Передатчик CH569 после HTRDY не меньше 10 тактов готовит FIFO, поднимает HTVLD, захватывает шину и
   передаёт заголовок, данные, CRC. HTVLD может падать посреди пакета, если FIFO опустел; приёмник
   берёт данные только при HRVLD.
4. В конце передатчик снимает HTVLD и HTREQ. Приёмник по снятию HRACT проверяет CRC и номер,
   записывает длину и USDF, выставляет флаг R_DONE.

Если обе стороны одновременно поднимают HTREQ, передаёт та, что в режиме «верхний» (RB_HSPI_MODE = 1).
Аппаратный ответ (RB_HSPI_HW_ACK): приёмник после правильного пакета сам отправляет байт 0xF0, без него
передатчик видит таймаут; в пакетном режиме (до 256 пакетов без участия программы) он обязателен.
BSP включает режим без ответа.

Фронты: RB_HSPI_TCK_MOD — по какому фронту HTCLK передатчик меняет данные, RB_HSPI_RCK_MOD — по какому
фронту HRCLK приёмник их берёт.

## Чего в даташите нет

- Начальное значение CRC, отражение битов и выходной XOR. В `hspi_tx` и модели это параметры (по
  умолчанию 0, без отражения, без XOR), настоящие значения — замер на шаге 0: CH569 шлёт пакет в ПЛИС
  или в SLogic16U3, затем подбор по известным данным. Порядок байт CRC на шине принят младшим вперёд.
- Как CH569 считает CRC при шине 16 бит: принято по байтам в порядке передачи, как при 8 битах.
- Задержки t1–t4 на временной диаграмме 10-3 даны без чисел. Передатчик ПЛИС после пакета ждёт снятия
  HTACK (с таймаутом) и выдерживает паузу `cfg_gap` тактов.
- Двигается ли ожидаемый номер у приёмника после пакета с ошибкой CRC. Модель считает, что да:
  передатчик без ответа номер уже увеличил.
